# Android build (Phase 1 foundation)

STATUS: the pipeline below is WRITTEN BUT NOT VERIFIED. No APK has been built yet. See "Known issues".

## What Phase 1 adds
- Capacitor 7 (`@capacitor/core`, `@capacitor/android`, `@capacitor/cli`, all `^7.0.0`) and `capacitor.config.ts`
  (appId `com.ntinginya.personallifeos`, webDir `dist`).
- Capacitor 7 needs Node 20+ and JDK 21 (matches `NODE_VERSION = "20"` in `netlify.toml`, so the web deploy is unaffected).
  Capacitor 8 needs Node 22+, so it was NOT chosen.
- The `android/` project is generated by `npx cap add android` (CI does this when the folder is absent). Nothing native is hand-written yet.
- The service worker is not registered inside the Android shell (`src/lib/platform.js`, `src/main.jsx`). The web/PWA build is unchanged.

## Build locally (needs Node 20+, JDK 21, Android SDK)
```
npm install
cp .env.example .env     # fill VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY only
npm test
npm run cap:add:android  # first time only
npm run android:debug    # builds web, syncs, runs gradle assembleDebug
```
APK: `android/app/build/outputs/apk/debug/app-debug.apk` (unsigned debug build, for testing only).

## GitHub Actions
Workflow: `.github/workflows/android-debug-apk.yml`. Runs on pushes to `Android-V1` and by hand ("Run workflow"). Never runs for `main`.
Required repository secrets (Settings -> Secrets and variables -> Actions):
- `VITE_SUPABASE_URL` - same value the web site uses.
- `VITE_SUPABASE_ANON_KEY` - the public anon key only. NEVER the service-role key. NEVER an AI key.
No signing secrets exist or are needed in this phase. Download the APK from the run's "Artifacts" section.

## Known issues (not fixed in Phase 1, by design)
1. AI Assistant will NOT work in the APK: `src/services/aiClient.js` calls a relative `/api/ai-chat`, and the server function has no CORS headers. Needs an approved backend URL + CORS change.
2. Sign-up confirmation and password-reset emails use `window.location.origin`, which inside the APK is `https://localhost`. Needs deep links and Supabase redirect-URL approval.
3. No `package-lock.json` exists in the repository, so installs are not reproducible. CI falls back to `npm install`. Commit a lockfile generated on a networked machine.
4. Offline reminders and native notifications are untouched (Phase 3). The existing IndexedDB reminder code is still unused.
5. `android/` is generated, not committed. Decide whether to commit it once the first build succeeds.
